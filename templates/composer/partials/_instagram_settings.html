{% comment %} Instagram placement panel (Blue Monkey Media fork). Lets you pick Reel / Story / Carousel / Feed image per Instagram account, plus share_to_feed and a cover frame for a Reel. Without this the placement came only from the automatic derivation in the publisher, which made a Story unreachable from the composer. New file: the fork keeps its own markup out of compose.html, which includes this once inside the `x-for accId in selectedAccounts` loop. Increment 3 added "Media for this account": a per-account file list stored as PlatformPost.platform_specific_media (form field `ig_media_ids_`), picked in _instagram_media_modal.html. When set, every check in this panel judges those files instead of the post's, and so does the server. From the enclosing scope: accId, charLimits, platformExtras, selectedAccounts, mediaKinds, hasVideoAttached, tiktokCoverPreview, openFramePicker, clearTiktokCover, formatTimecode, platformIconSvg. From outside it, the `bmmMedia` Alpine store and `window.bmmInstagramSpecs`, both set up by static/js/instagram-specs.js -- the panel degrades to increment 1's behaviour if that script is missing rather than throwing. Two kinds of message come out of this panel and the difference is the point. A **stop** greys the placement out and the server refuses the save too: Instagram would reject the container, asynchronously, minutes later. A **warning** is amber and blocks nothing: it publishes, cropped or trimmed, and you are told which before you schedule instead of finding out in the grid. The cover reuses the TikTok frame picker as-is, including its Alpine keys (`video_cover_timestamp_ms`, `tiktokCoverPreview`). An account is either TikTok or Instagram, so the keys cannot collide, and reusing them keeps the picker's JS untouched. The form field below is what translates it: `ig_cover_timestamp_ms` becomes `thumb_offset` in apps/composer/instagram_extras.py. That translation has to run the other way too: a saved post comes back with `thumb_offset` and without `video_cover_timestamp_ms`, and a panel that only reads the latter would show no cover and send an empty field, which drops the cover on the next save. The x-init below is that reverse step. "Automatic" is a real option and not just the absence of one. It sends `auto`, which the server stores as "no post_type", so the publisher derives the placement as it always did. An empty value would not do: empty means "the panel said nothing, keep what is stored". {% endcomment %}
